# ADR-0006: Email/password + server-side sessions; Google OAuth as an inert adapter

## Status
Accepted

## Context
Spec §4 wants secure email auth, optional Google login, session security, and RBAC. Google OAuth
requires a real `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET` and a registered redirect URI — not
obtainable in a local build (spec §2 rule 14: TODO only for credentials that cannot be completed
locally).

## Decision
Primary auth: email + Argon2id-hashed password, server-side session in Redis, httpOnly + secure +
SameSite=Lax cookie, session fixation prevented by rotating the session ID on login/privilege
change. `POST /auth/oauth/google` route and the corresponding "Continue with Google" UI button
exist and are wired to the real OAuth code-exchange flow, but the button renders disabled with an
explanatory tooltip when `GOOGLE_CLIENT_ID` is unset (the default in `.env.example`) — this is
the TODO marker required by spec §2 rule 14, expressed as inert-but-real code rather than a
comment.

## Consequences
Local demo and seed users authenticate via email/password only. Enabling Google login in a real
deployment is a config change, not a code change.
